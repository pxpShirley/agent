# 星澜 · 特色能力设计（v5 提案）

原型：`prototype/xinglan-signature.html`（视觉唯一真相源，改视觉先改它）

---

## 0. 设计主张

星澜从来不是一个聊天框。**栖光常驻在右下角、有 8 种情绪、有呼吸的光晕，暖金只留给「需要你」**——这套语言是"在场"的语言。

所以本轮**不设计新按钮，只设计新的感知方式**。下面五件事都不是加功能，而是**让已有的数据换一种活法**：

| # | 设计 | 一句话 | 它把什么换了一种活法 |
|---|------|--------|---------------------|
| 1 | 一天的天气 | 待办不该是清单，该是今天的密度 | `reminders` → 时间光带 |
| 2 | 记忆星图 | 让检索算法第一次被看见 | `selectMemories` 的衰减 → 可视图 |
| 3 | 沉默的提醒 | 提醒不是打断，是环境里的一个变化 | 通知 → 余光 |
| 4 | 没说出口的 | 读你做过什么，而不是你说过什么 | 顺延/打卡 → 偏好推断 |
| 5 | 共度的痕迹 | 日志是给机器看的，痕迹是给关系看的 | `agent_spans` → 用户可见 |

共同约束：**数据零新增或极少新增**，五件里有四件是纯"换看法"。

## 1. 一天的天气

**它回答什么**：列表回答"有哪些事"，光带回答**"今天是什么形状"**。

同一份 `reminders` 数据，按 `due_ts` 铺在 06:00–24:00 上：

- 位置 = 到期时间；大小 = 是否有子步骤（越复杂越大）
- 冰青 = 还没到；**暖金 = 已逾期（需要你）**；暗纹 = 已完成（**留痕，不消失**）
- 底部密度条 = 每 2 小时一桶的待办数，一眼看出哪段挤
- 竖线 = 此刻（用 `useNow.ts` 已有的时间源）
- 顶部一句话天气由数据算出：「上午是空的，下午最挤（3 件叠在一起），另有 1 件已经晚了」

**要改什么**
- 新增 `src/components/DayWeather.tsx` + CSS，读 `GET /api/reminders`（或现有 schedule 接口）
- 逾期判定**只用 `due_ts`**（`due_at` 仅供展示——架构硬约束 §一）
- 一句话天气做成纯函数 `describeDay(tasks, now)`，挂探针（参照 `scripts/*-probe.ts` 惯例）

**风险**：低。纯读 + 纯展示，不碰写路径。

## 2. 记忆星图

**它回答什么**：为什么它记得这条、淡了那条？

`server/memory.ts` 的 `selectMemories` 里已经跑着一个**新鲜度权重（30 天半衰）**，但没人看得见它。星图做的只是**把算法画出来**：

- 亮度 = `Math.pow(0.5, ageDays/30)` —— 与服务端**同一个公式**，不是近似
- 大小 = 被唤起次数
- 位置/连线 = 按 `kind`（preference / fact / plan / note）聚成星座
- 濒临遗忘的那颗 → 暖金脉动环，栖光轻声问「还留着吗？」

**要改什么**
- 后端：新增 `GET /api/memories/starmap`，返回 `{kind, ageDays, recallCount}`。
  ⚠️ **`recallCount` 目前没有落库**，需要在 `selectMemories` 命中时 +1（轻量写入，或先退化为用 `updated_at` 近似）
- 前端：`MemorySky.tsx`（canvas）。⚠️ **canvas 必须按 `devicePixelRatio` 缩放**；⚠️ **柔化绝不用 `ctx.filter='blur()'`**（帧率 30→15），用 `createRadialGradient` 代替

**风险**：中。要动 `selectMemories`（记忆检索是单一真相源，改动必须让 `memory-select-probe.ts` 26 项继续全绿）。

## 3. 沉默的提醒

**它回答什么**：提醒最贵的成本不是算力，是**打断**。

- 到期前**只在余光里变化**：栖光光晕边缘泛起暖金涟漪，越近越快越亮
  - 3h：几乎无 → 1h：一丝 → 30m：缓慢脉动 → 10m：明显
- **真逾期了才升级成卡片**，进入「人的环」（`scheduler.ts` 已有的 `reminder_due` 卡片 + 完成/顺延/问栖光动作）
- **免打扰时段内永不升级**——复用 `detectQuietHours()`（已从"11 点后少打扰"这类记忆里解析出时段）

**要改什么**
- 后端：`scheduler.ts` 的 tick 增加一节，**提前 3 小时**生成一张 `kind:'ambient'` 的轻量标记（不进卡片池、不推送），只把 `urgency ∈ [0,1]` 写给前端
- 前端：`.nx-presence-orb` 读 urgency 驱动 `--urg`（原型里已验证：CSS 变量同时驱动涟漪透明度与动画周期）
- ⚠️ **确认 UI 单一入口**：待确认只有「人的环」浮层 **`.nx-human-moment`**；涟漪是**氛围**，不是第二张确认卡，两者不得同现

**风险**：低-中。动 `scheduler.ts` 的 tick，需确认 `activeOwners()` 上限 5 + `proactiveCardExists` 去重不被绕过（别把卡片池冲爆——这是踩过的坑）。

## 4. 它记得你没说出口的

**它回答什么**：顺延一直被当成"用户没做到"，其实它是**最诚实的偏好信号**。

星澜读的不是你说过什么，是你**做过**什么：

| 观察到的行为 | 推断 | 建议 |
|---|---|---|
| 同一条顺延 ≥3 次 | 不是忘了，是日子不对 | 挪到每月 5 号？ |
| 连续 6 天 22:00 后才整理 | 夜里才是你的整理时间 | 把每日复盘定在 22:30？ |
| 某条 47 天未动 | 现在不是时候 | 先收进「以后」，别让它天天提醒你 |
| 周五 18:00 心情均值最低 | 疲惫集中在这时 | 那时放一首你常听的？ |

**要改什么**
- ⚠️ **顺延次数目前没有落库**。`server/db/reminders.ts:248` 的顺延函数执行时，需要写一条 `snooze` 记录（或给 reminders 加 `snooze_count` 列 + `ensureColumn` 迁移——`agent_runs` 已有同款迁移先例）
- 推断层写成**零依赖纯函数** `server/insight.ts`，与 `server/clarify.ts` 同构（可测、不靠模型）
- ⚠️ **只在被问到 / 主动服务卡片里出现，绝不塞进对话主回复**——提示词第 0 条：禁止汇报后台状态

**风险**：中。要加一张写路径。但纯函数 + 探针可控。

## 5. 共度的痕迹

**它回答什么**：日志是给机器看的，痕迹是给关系看的。

复用的正是路线图 **P0 trace** 要采集的那份数据——只是它不只躺在工程师的调试面板：

- 时间线 = 你说了什么 / 栖光做了什么 / 那天的心情 / 那天放过的歌
- 里程碑打暖金星标：第一次记住你的偏好、第 100 条记忆、第一次完成一件大事
- 数据来源：`checkin_mood`（`recentMoods`）+ `memories` + `reminders` + 播放记录

**要改什么**
- 与 P0 `agent_spans` **共用同一份采集**，只是渲染面向用户
- ⚠️ **Trace 红线不变**：只读观测，**任何情况下不得把 trace 文本回灌模型上下文**。用户可见 ≠ 模型可见，这两件事必须物理隔开

**风险**：低（本身依赖 P0）。建议**排在 P0 之后**。

## 6. 优先级建议

```
先做（数据现成、纯展示）
  1 一天的天气   ← 零新增数据，最高性价比
  3 沉默的提醒   ← 复用 detectQuietHours，最贴 DNA

再做（需要小额写路径，但纯函数可控）
  2 记忆星图     ← 需要 recallCount
  4 没说出口的   ← 需要 snooze 记录

最后（依赖 P0）
  5 共度的痕迹
```

**与现有路线图的关系**：本提案**不替换** P0–P3，而是给它们一个"用户能感知到的出口"。
其中 ② 与 P0（trace）共享数据、共享"让不可见变可见"的哲学——**先观测，再优化**这条判断依然成立，P1/P2 继续压着等数据。

## 7. 落地纪律（沿用项目既有约束）

- 视觉先改 `prototype/xinglan-signature.html`，再回灌 React
- 每个新能力配 `scripts/*-probe.ts` 并挂 `npm test`
- 断言测**用户得到了什么**，不测内部走了哪条路
- 完成后 `tsc -b --force` + `npm test` + `npm run build` 全绿
- 配色纪律：冰青 = 系统语言，暖金 = **仅**「需要你 / 待确认」
