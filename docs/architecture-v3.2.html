阻断 D1「唯一出口」自相矛盾
目标态宣布 assembleContext() 是主循环获取上下文的唯一出口，但目标态里没有给产物内容注入（tryFindArtifactContent() 把产物全文直拼 user 消息）安排归属 → 目标态落地后必然存在两个出口。应在目标态明确：并入装配器，或登记为受审计的豁免。
assembleContexttryFindArtifactContent
阻断 D2装配器契约自相矛盾
目标态给的是同步签名 assembleContext(): AssembledContext，而滚动摘要是 async compactOldTurns()； 同时 L0+ 又要求"每轮检查预算"。→ 目标态需拆成 turn 级同步装配 + iteration 级守卫，并定义"摘要未就绪时读旧摘要 + compacted=false"。
同步 vs 异步guardBudget
阻断 D3预算器缺测量闭环
目标态的核心卖点是"长度由 token 窗口算、禁止魔法数字"，但目标态没有安排 token 采集（未解析 usage、无 token 列）→ 目标态只能用字符系数估，无法自证，等于把 6000 换成 1.6。目标态必须把 usage 采集列进 P0。
usage 采集calibration
高 D4召回 query 语义缺失，与自己的验收冲突
recallForPrompt(owner, query, limit) 未定义 query 从哪来；而首批用例里"多轮指代（明天上午）"恰是 query 最弱的场景 → 目标态的验收证明不了目标态的功能。应定义 query = 最近 K 轮拼接，并给中文匹配规则。
query 语义用例错配
高 D5L4 安全网盖不住 L1/L2
4 条用例里 3 条考的是提示词行为，只有"产物读取"沾 L0 边 → 改上下文引擎时没有回归网。 目标态需按层分组，并补"长上下文事实可引用 / 预算不越界 / 兜底路径"三类。
E1–E7按层分组
高 D6并行工具的收益与优先级错配
目标态把它排"最高优先"，但目标态里每轮一次的 LLM 流式调用不可并行、SQLite 为同步驱动 → 受益面仅网络型工具； 而"副作用工具保留串行"所需的分类在目标态里也没有数据来源（会退化成硬编码名单）。应降为 P2 并补 Tool.sideEffect。

L1
Context Engine · 上下文引擎（目标态）
server/context/{budget,summarize,retrieval,assemble}.ts
目标态 · P1 最高优先

不再靠"截断"维持上下文，改为预算驱动的装配器。铁律：上下文只有一个出口 —— 目标态必须把产物注入旁路一并收口（D1）， 并把"预算"建立在实测 token 上（D3）。

① Token 预算器
allocate() 把窗口切给 system/memory/tools/history；resolveWindow(model) 读模型上限。 依赖 P0 的 usage 采集：无实测数据则系数即魔法数字。
budget.tscalibration
② 滚动摘要
compactOldTurns() 保留近 K 轮原文，更早的异步压成摘要（只压事实结论，不删 DB）。 装配只读已生成摘要，未就绪则 compacted=false 并后台补做。
summarize.ts异步·幂等
③ 装配器 · 双 API修订 D2
assembleContext()（turn 级·同步·唯一出口）+ guardBudget(messages)（iteration 级裁剪）。 两者拆开，目标态才能同时成立"唯一出口"与"每轮查预算"。保留旧实现一版作灰度回退。
assemble.tsguardBudget
④ 记忆召回钩子修订 D4
相关性召回（见 L2）。先定义 query 语义：取"最近 K 轮拼接"而非仅当前句，否则多轮指代无关键词命中 → 必走回退分支，验收测不到收益。
retrieval.ts近 K 轮 query可换实现
⑤ 旁路收口清单修订 D1
目标态需登记全部上下文注入点并归入装配器：buildHistory()（历史）、buildMemoryContext()（记忆）、 tryFindArtifactContent()（产物真实内容）。三者之外不得再有直接拼 messages 的地方 —— 这是可 grep 的验收条件。
