# 星澜 · 全新用户界面设计方案 v4

> 方向：**从零重做整套界面** · **两端兼顾响应式** · **深空星境（暗色 + 冰青 + 玻璃）**
> 日期：2026-10-07　交付物：本文档 + `prototype/xinglan-ui-v4.html`（高保真可交互原型）
> 落地前请以原型为准（本项目惯例：原型是视觉唯一真相源）。

---

## 1. 先诊断：现有界面为什么"不够好用"

在设计新方案之前，先把现在的问题讲清楚 —— 否则"重做"只是在换皮肤。

| # | 问题 | 为什么伤体验 |
|---|---|---|
| 1 | **栖光占了半个屏幕** | 「此刻」页左侧 presence 占约 50% 宽度。它很好看，但用户真正的任务（对话、看待办、找记忆）被挤到半屏。形象是产品灵魂，但灵魂不该霸占工作台。 |
| 2 | **导航命名来自内部术语** | 「我的 · 灵境」里塞了记忆 + 提醒 + 产物三类资产；「治理」里塞了设置 + 反馈 + 运行参数。二级密度过高，且"治理""灵境"是团队词汇，不是用户词汇。 |
| 3 | **浮层层级偏多** | 命令面板、仪表盘抽屉、历史抽屉、顶部反馈栈、人的环 —— 5 类浮层叠加，Esc 关哪一层需要记忆。 |
| 4 | **缺少标准生产力控件** | 没有搜索、筛选、排序、空态引导、撤销。资产少时无所谓，一多就"找不到、改错了没法回退"。 |
| 5 | **移动端只是"没塌"** | 桌面范式直接缩小，左 Rail 在手机上仍占 84px，触控目标偏小。 |

**一句话结论**：把「展示栖光」的结构，换成「用户干活」的结构；栖光从**占屏**退为**在场**。

---

## 2. 设计原则（这六条是后面所有决策的依据）

1. **一屏一事** —— 每个页面只服务一个主任务，减少希克定律式的选择成本。
2. **资产为主干，形象为陪伴** —— 记忆 / 待办 / 产物是用户真正的资产，做成标准列表页；栖光常驻右下角，需要时才放大。
3. **符合习惯优于标新立异** —— 导航在左（桌面 F 型视线）、底部 tab（手机拇指热区）、主按钮在右下（前进方向）、破坏性操作二次确认、改完给撤销。
4. **状态永远可见** —— 加载、空、错误、离线、待确认，每一种都有明确且不打断的表达。
5. **暖金只属于「人的环」** —— 冰青是系统语言；暖金仅在"需要你决策"时出现，这条纪律不因改版而松动。
6. **动效服务于理解** —— 只用于解释"发生了什么"，不用于表演；一律尊重 `prefers-reduced-motion`。

## 3. 信息架构（重定义）

```
顶栏  品牌 · ⌘K 唤起能力                     状态 ● 在线   设置
─────────────────────────────────────────────────────────────
导航(240)  │  主区（当前任务）                │ 在场面板(320)
· 对话     │  ← 一屏一事                     │ · 栖光（8 种情绪）
· 记忆     │                                 │ · 此刻感知
· 待办     │                                 │ · 待你确认（金）
· 产物     │                                 │ 可折叠
· 设置     │                                 │
─────────────────────────────────────────────────────────────
                                        [栖光球]  ← 折叠/移动时唯一入口
```

### 导航五项（用户词汇，不是内部术语）

| 项 | 内容 | 为什么独立成页 |
|---|---|---|
| **对话** | 与栖光的来往（默认页） | 最高频动作，打开即达 |
| **记忆** | 它记得的关于你的事（含冲突合并） | 用户会想"它到底记住了什么" |
| **待办** | 提醒 / 习惯（含周期、子步骤、打卡） | 唯一有"完成"动作、有进度语义的资产 |
| **产物** | 行程 / 报告 / 清单（含版本与回滚） | 长内容，需要独立阅读与导出 |
| **设置** | 外观、引擎、数据导出 | 原「治理」改名，符合通用习惯 |

### 栖光的新位置：常驻在场，不占工作台

- **桌面**：右侧「在场面板」常驻（可折叠），保留 8 种情绪演出 —— 上一版做的形象演出完全保留，只是容器变小。
- **折叠 / 平板 / 手机**：收成右下角 **在场球**，点击展开"共同时光"浮层。
- **需要你确认时**：在场球转暖金并呼吸，主区居中弹出确认卡 —— 「人的环」纪律不变，且不再出现两份确认卡。

## 4. 布局与响应式

| 断点 | 布局 | 关键变化 |
|---|---|---|
| **≥1440** | 顶栏 56 + 导航 240 + 主区 1fr + 在场 320 | 三区全开 |
| **1280–1439** | 在场面板收窄到 280 | 主区优先 |
| **1024–1279** | 在场面板折叠为在场球 | 主区获得全宽 |
| **768–1023** | 导航收窄为图标 Rail（72px） | 保留桌面范式 |
| **<768** | 导航变底部 5 tab（56px）+ 单列 | 拇指热区、触控 ≥44px |
| **<480** | 紧凑间距、字号 −1、卡片全宽 | 单手可达 |

## 5. 视觉语言（设计令牌 · 深空星境）

### 颜色
```
底：    --bg #050912   --bg-1 #0a1120
面：    --surface rgba(18,28,48,.62)   --surface-solid rgba(14,22,40,.86)
主色：  --brand #6fd6ff   --brand-600 #3aa6e0   --brand-glow rgba(111,214,255,.45)
强调：  --gold #f6c062（仅「人的环」）
语义：  success #5ee6a8   warn #ffc46b   danger #ff7a7a   info #6fd6ff
文本：  --text #e8f2ff   --text-2 #a9bdd8   --text-3 #6f829d
边框：  --border rgba(140,170,220,.16)
```
对比度实测：`--text` on `--bg` ≈ **15:1**，`--text-2` on `--surface` ≈ **8.4:1**，`--text-3` on `--surface` ≈ **4.6:1**（均达 WCAG AA）。

### 字与间距
- 字号 12 / 13 / 14 / 16 / 19 / 24；行高 1.6；字重 400 / 500 / 600 / 650
- 数字与时间戳统一 `font-variant-numeric: tabular-nums`（防跳动）
- 间距严格走 4 的栅格：4 / 8 / 12 / 16 / 20 / 24 / 32
- 圆角：控件 8 · 卡片 12 · 面板 16 · 胶囊 999

### 动效
- `--dur-fast .14s` / `--dur .22s` / `--dur-slow .42s`，缓动 `cubic-bezier(.22,.61,.36,1)`
- 只用于"解释发生了什么"：内容淡入 0.22s、浮层 0.28s、Toast 0.2s
- `prefers-reduced-motion: reduce` 下全部降级为瞬时

### 背景
深空星境：canvas 星空（三层视差 + 呼吸闪烁 + 偶尔流星）+ 顶部/底部压暗 + 边缘暗角。
**必须按 devicePixelRatio 缩放**（现有实现没做，高分屏是糊的）。星空只做底，不抢戏。

## 6. 核心组件规范（含状态）

| 组件 | 规格 | 必备状态 |
|---|---|---|
| 按钮 | 高 32/36/40；primary(渐变) / secondary / ghost / danger / subtle | default / hover / active / focus-visible / disabled / loading |
| 输入框 | 高 36，聚焦冰青 2px 环 | default / focus / error（内联文案）/ disabled |
| 列表卡 | 12 圆角，hover 抬 2px + 边框转冰青 | default / hover / selected / disabled |
| 标签 chip | 胶囊，用于筛选与分类 | default / active / removable |
| 模态 | 居中 + scrim + 焦点陷阱 | 打开 / 关闭（Esc） |
| Toast | 右下角，4s 自动消 | 成功 / 失败 / **可撤销（5s）** |
| 骨架屏 | 加载 >200ms 出现，>1s 补进度条 | — |
| 空态 | 图标 + 一句人话 + 一个主行动 | 首次 / 无结果 |
| 确认卡（人的环） | **暖金**，唯一确认入口 | pending / 已处理（留记录） |

## 7. 关键流程

1. **发起对话**：输入 → 流式吐字 → 执行步骤可见（规划/检索/执行/复核）→ 产物落库 → 可能被问确认 → 完成回执。
2. **需要你确认**：在场球转金 → 主区居中确认卡（4 选：直接批准 / 改后批准 / 转交 / 稍后 / 取消）→ 决策后对话流内留一条结果记录。
3. **待办打卡**：列表行内一键完成 → Toast「已完成 · 撤销」→ 周期项自动滚下一期。
4. **记忆冲突**：冲突徽标 → 一键"保留最完整的一条并合并其余" → 二次确认 → Toast 可撤销。
5. **⌘K 唤起能力**：全局面板，模糊匹配能力 + 资产，回车直达。

---

## 8. 交互细节（"符合用户习惯"的具体条款）

- 导航当前项：左侧 2px 冰青指示条 + 底色高亮 + `aria-current="page"`
- 主按钮位于内容区右下（前进方向）；破坏性操作需二次确认
- 所有写操作给 Toast + **撤销**（5s 内可回退）
- ⌘K 全局唤起；Esc 逐层关闭浮层；Tab 焦点始终可见（2px 冰青环）
- 加载 >200ms 显示骨架，>1s 显示进度；失败给"重试"而非只报错
- 触控目标 ≥44×44（移动端）；桌面点击区 ≥32
- 首次进入给空态引导，不给空白

---

## 9. 可访问性

- 正文对比度 ≥4.5:1，大字 ≥3:1（见 §5 实测值）
- 所有交互元素可键盘到达，焦点可见
- `aria-label` / `aria-current` / `role=dialog` / `aria-live` 播报状态变化
- 动效可关闭（`prefers-reduced-motion`）
- 颜色不是唯一信息载体（状态同时有图标/文案）

## 10. 与现有系统的差异 & 落地路径

| 维度 | 现在 | v4 |
|---|---|---|
| 导航 | 此刻 / 我的 / 治理 | 对话 / 记忆 / 待办 / 产物 / 设置 |
| 栖光 | 占主区 50% | 右侧在场面板 ↔ 右下在场球 |
| 浮层 | 5 类叠加 | 收敛为 模态 / Toast / 命令面板 3 类 |
| 资产 | 混在「我的」三个 tab | 各自独立成页，带搜索/筛选/空态/撤销 |
| 移动端 | 桌面范式缩小 | 底部 tab + 单列 + 大触控区 |

**落地分五阶段**（每阶段可独立验收）：
1. 令牌层 + 三区布局骨架（不动业务）
2. 五个页面（对话 → 待办 → 记忆 → 产物 → 设置）
3. 栖光在场面板 + 在场球 + 8 种情绪演出接入
4. 移动端断点（底部 tab / 单列 / 触控尺寸）
5. 打磨：骨架、空态、撤销、可访问性、动效降级

## 11. 验收标准（DoD）

- [ ] 五个页面均可在 ≤3 次点击内到达任意资产
- [ ] 每个写操作都有 Toast + 撤销
- [ ] 确认 UI 全局只有一处（人的环），且用暖金
- [ ] 1024 / 768 / 480 三个断点布局不塌、不遮挡、无横向滚动
- [ ] 键盘可完成全流程（含 ⌘K 与 Esc 逐层关闭）
- [ ] 正文对比度全部 ≥4.5:1
- [ ] 开启"减少动态效果"后无位移动画
- [ ] `prefers-reduced-motion` 与 lite 模式下星空降级为静态/低密度
