# 星澜 AI 生活管家 · 产品 Redesign 方案（Agent-Native）

> 版本: v0.1 · 2026-08-16
> 范围: 交互模式 / 页面设计 / 功能设计 的重构方向，不含逐文件实现细节。
> 背景: 当前版本已具备「百炼 ReAct 引擎 + 7 个工具 + 活动流（agent_runs）+ 例外收件箱（pending_questions）+ 主动调度器（Scheduler）」。本次重构目标是把星澜从「能干活但等你吩咐的管家」升级为「主动张罗、交付产物、越来越懂你」的 Agent 搭档。

## 1. 现状诊断

### 1.1 已具备的能力（资产）
- **真实引擎**：`server/llm/bailian.ts` 驱动通义千问（qwen3.7-flash），支持 function calling 的 ReAct 循环（≤6 轮）。
- **七件工具**：`recall_memory / save_memory / checkin_mood / set_reminder / get_schedule / ask_user / web_lookup`（最后一项已打通免 Key 的 dashscope 检索）。
- **活动流**：`agent_runs` 已能记录每轮 agent 的自主动作（真实会话现已落库）。
- **人在环**：`pending_questions` 支持「改后批准 / 转交人工 / 稍后处理 / 取消」四类决策。
- **主动调度**：`Scheduler` 每 60s 触发一次，但当前只做内部检查，未形成「主动推送给用户」的链路。

### 1.2 核心差距（五个维度）

| 维度 | 现状 | 最佳实践 | 差距 |
|---|---|---|---|
| 主动性 | 用户不输入，Agent 静止 | 感知上下文后主动发起 | 缺主动推送链路 |
| 产物 | 回复是一段聊天文本 | 结构化、可编辑、可分享的产物 | 无 Artifact 层 |
| 记忆 | 被动存取，不构建画像 | 持续演化的用户模型 | 无记忆图谱 / 画像视图 |
| 智能体结构 | 单 Agent 一肩挑 | 规划 / 研究 / 执行 / 评论分工 | 无多 Agent |
| 目标 | 无长期意图 | 跨轮 / 跨天推进的目标 | 无 Goal 机制 |

**结论**：当前是「带工具调用的聊天机器人 + 运维式指挥舱」，不是真正意义上的 AI Agent。

## 2. 设计原则（北极星）
1. **主动优先**：默认由 Agent 发起，人只在关键节点介入。
2. **产物即价值**：Agent 的交付必须是可接手的对象，而非一次性文本。
3. **透明可信**：每一次工具调用、每一步推理都可见（复用 activity stream）。
4. **人在环最小化摩擦**：确认是卡片，不是阻塞式弹窗。
5. **持续学习**：人的每次决策都沉淀为偏好与规则。

## 3. 目标交互模型：主动闭环

六步闭环（对齐现有 ReAct，但补上「主动」与「学习」两端）：

`感知 → 规划 → 执行（工具 / 多 Agent）→ 产物 → 人在环 → 学习 →（回到感知）`

- **感知**：读取记忆、日程、外部事件（天气 / 股价 / 日历变更）、用户画像。
- **规划**：拆子任务，决定是否需要研究 / 检索 / 多步。
- **执行**：调用工具；复杂任务移交多 Agent。
- **产物**：生成可编辑、可分享的对象（行程卡 / 报告 / 清单）。
- **人在环**：高风险或不确定前，推确认卡。
- **学习**：记录 confirm / escalate / defer / cancel，更新偏好与规则。

**多入口**：对话只是入口之一。另含语音、「此刻」卡片按钮、快捷指令、外部触发（日历 / 邮件 webhook）。

**目标（Goal）机制**：用户设定长期意图（如「帮我养成早起」），Agent 跨多次会话推进，在「目标追踪」页展示进度并定期汇报。

## 4. 信息架构与页面设计

五大界面（取代当前的「对话页 + 指挥舱 + 收件箱」）：

1. **此刻主页（首页）**：主动事项 + 进行中 + 待你确认 + 一句话发起框。打开即有内容，而非空白输入框。
2. **产物画布**：行程 / 报告 / 清单的结构化呈现，可编辑、可导出、可分享。
3. **记忆图谱**：关于你的用户模型（偏好 / 习惯 / 约定 / 情绪趋势）。
4. **目标追踪**：长期意图与进度，Agent 主动推进记录。
5. **例外收件箱**：人在环（沿用并强化现有 pending_questions）。

## 5. 功能设计

### 5.1 Artifact 层（产物即一等公民）
- 新增 `artifacts` 表：`type`（itinerary|report|checklist）、`schema`、`content`（JSON）、`owner`、`session_id`、`version`。
- 工具 `create_artifact` / `update_artifact` 由 Agent 在交付时调用。
- 前端以可编辑卡片渲染，支持导出（Markdown / .ics）与分享。

### 5.2 多 Agent 分工（Phase 4）
- **Planner**：拆任务、定步骤。
- **Researcher**：调用 `web_lookup` 做检索（复用 dashscope）。
- **Executor**：落库 / 设提醒 / 写产物。
- **Critic**：复核产物质量与风险。
- 实现：在 `runBailianAgentTurn` 之上包一层编排，或子 agent 串行。

### 5.3 学习闭环
- 监听 `pending_questions` 的决策（approve / escalate / defer / cancel）。
- 沉淀为 `user_preferences` / `agent_rules`（如「用户偏好邮件而非微信」）。
- 下次规划时注入 system prompt。

### 5.4 出站动作闭环
- 强化 `OUTBOUND_WEBHOOK_URL`：确认后真正 POST（日历 / 微信 / 邮件）。
- 「改后批准」允许用户在卡片内修改草稿再执行。

## 6. 技术落地路线（分阶段）

- **Phase 0（已部分完成）**：真实引擎 + 工具 + 活动流 + 人在环。`agent_runs` 真实落库、`web_lookup` 免 Key 已就绪。
- **Phase 1 主动循环 + 此刻主页**：把 Scheduler 接到「主动生成待办 / 提醒并推首页」；新建「此刻主页」聚合 agent_runs / pending / 主动建议。
- **Phase 2 产物画布 + Artifact 层**：`artifacts` 表 + `create_artifact` 工具 + 可编辑卡片。
- **Phase 3 记忆图谱 + 目标追踪 + 学习闭环**：用户模型视图、Goal 表、反馈沉淀。
- **Phase 4 多 Agent 编排 + 出站闭环**：Planner / Researcher / Executor / Critic + 真实出站。

## 7. 成功度量
- **主动发起率**：Agent 主动推送占比。
- **产物率**：含 Artifact 的交付占比。
- **人在环通过率**：confirm 占比（越高越信任）。
- **目标完成率 / 次日留存**。

## 8. 风险与取舍
- 主动性过强 → 打扰。需用「重要性 + 确定性」阈值控制推送频率。
- 多 Agent 成本与延迟：Phase 2 后再做，先单 Agent + 产物验证价值。
- 记忆隐私：画像需可查看、可删除。

## 9. 待决策项
- 首页默认展示「主动事项」还是「对话」？建议默认主动。
- 产物是否需要 iCal / 微信直连导出？（取决于出站 Key）
- 是否现在就引入多 Agent，还是先用单 Agent + 产物验证价值？
