Executive Summary

执行摘要

本文基于已落地的「关系界面」系统（React + TS + Vite + TDesign + Node/Express + SQLite + @tencent-ai/agent-sdk）进行两件事：① 在不破坏现有技术栈、架构风格与体验的前提下做功能扩展设计；② 对「星澜」这一角色进行完整形象重定义——角色定位、命名含义、视觉标识、色彩与风格规范、声音语气，并确保其融入每一个现有功能场景。

Design Principles

设计原则（理念锚点）

在定义角色与界面之前，先确立不可妥协的四条原则。后续所有视觉、交互、扩展决策都以此为准绳；任何与原则冲突的方案都须回到此处复议。

P1

唯一焦点

每屏只立一个视觉主角——星澜。其余信息退为氛围与浮层，绝不抢戏。

P2

静水深流

克制动效与留白：呼吸、浮现、淡入，而非闪烁、弹跳、堆叠。

P3

冷暖有界

冷青是系统的语言，暖金只留给「人的时刻」——需要你、确认、人的环。

P4

渲染而非罗列

对话结构化渲染（Markdown），记忆/目标以图谱形态表达，信息以「形态」而非列表呈现。

Xinglan Persona

三、星澜形象完整定义

星澜不是功能、不是客服、不是工具列表，而是关系界面中「在场的存在」。以下从角色、命名、视觉标识到声音，给出可落地的完整规范。

3.1 角色定位

一句话定位

星澜是你与复杂系统之间的在场陪伴者与协同伙伴——它记住你、理解你、替你跟进，并在每一个需要判断的时刻把选择权交还给你。

三重身份

① 守护者：持续在场、记住关系事实；② 协作者：规划/检索/执行/复核替你推进；③ 守门人：仅在「需要你」时打断，把决策权留给人。

3.2 命名含义

星

星 · XĪNG

星海、远方、指引、恒定。代表在浩瀚信息之海中稳定存在的「光点」——始终在场、可被找到、不随波动消失。

澜

澜 · LÁN

波澜、流动、呼吸。代表动态与温度——不是死寂的光，而是泛起涟漪、有节奏地回应你的「活的存在」。

星澜 · XINGLAN = 星海微澜

在浩瀚的信息星海中，泛起一缕温柔而恒定的波澜。它时时在场、静静守护，于你需要时泛起回应，于你沉默时归于静水。英文名 XINGLAN 音意兼取，可作独立品牌标识。

3.7 人的环 · Human's Ring（确认仪式规格）

「人的环」是星澜把决策权交还给你时的唯一暖金时刻，是产品信任关系的核心仪式。它不是一个普通弹窗，而是一次「暂停系统、请你出场」的庄重提示。

视觉
  • • 暖金光环自星澜核心向外扩散 1–2 圈涟漪（非冰青）。
  • • 当前界面其余元素降饱和 / 加暗罩，焦点收束到确认卡。
  • • 确认卡沿用 --gold-soft 底 + --gold 边 + --shadow-soft。
  • • 提供 确认 / 调整 / 稍后 三动作；默认聚焦「确认」。
交互与边界
  • • 触发：confirm:open；关闭：confirm:resolve。
  • • 非阻塞：可「稍后」收起为右下角暖金角标，不卡流程。
  • • 超时：未处理自动降级为感知浮层（失去暖金独占）。
  • • 可访问：焦点陷阱 + Esc 关闭 + 读屏播报。
Anthropomorphic Persona

四、星澜拟人化形象设计（外观 · 性格 · 行为）

在 §3 抽象标识与角色定位之上，进一步把星澜落为可感知的「拟人化存在」：萌系 mochi 精灵承载外观，情绪与性格驱动其表情与行为。设计与运行态（XinglanCore 星核内嵌该精灵）同源冰青、一致气质。

4.1 外观特征（Anthropomorphic Appearance）

圆润 · 生命感 · 在场
  • 体态：圆润 mochi 体 + 小脚，柔和不具攻击性。
  • 眼睛：大而柔的双眼 + 双高光；随鼠标转向你，始终「看着你」。
  • 腮红：淡粉腮红，情绪升温（开心/害羞）时加深。
  • 小嘴：安心微笑；担忧时下垂、开心时上扬成笑眼。
  • 头顶柔星：品牌印记，呼应 §3.3 标识。
  • 漂浮微光：圆点柔光环绕，强化「活的存在」。
  • 生命感：呼吸缩放 + 周期眨眼 + 说话时柔弯月眼。

与 §3.3 的关系：标识（同心涟漪·一点星核）是抽象符号，拟人化精灵是具象角色——二者同源冰青，精灵被嵌入 XinglanCore 星核中心，成为星澜的「生命体」本体。

Interaction Architecture

五、交互逻辑架构（清晰 · 职责分离 · 可扩展）

将散落的反馈与状态逻辑收敛为四层结构：事件总线解耦生产与消费、状态机统管导航、反馈控制器聚合界面操作、处理器注册表承载业务响应。新增关注方零改动事件源。

5.1 四层结构

LAYER 1

事件总线 EventBus

Typed 事件分发。生产方只管 emit；消费方 onType 订阅。完全解耦。

LAYER 2

状态机 StateMachine

home / memory / goals / loop 具名状态 + 切换守卫，替代散落数字。

LAYER 3

反馈控制器 Feedback

toast / success / whisper 三类界面操作反馈统一驱动，职责单一。

LAYER 4

处理器注册表 Handlers

业务响应（对话/确认/导航）以处理器注册，易于新增与编排。

5.3 界面操作反馈

ui:toast

轻提示

顶部短暂浮现（~1.9s），用于「我在听」「已收下」等轻量回执。

ui:success

成功态

冰青脉冲（~2.2s），任务收下/完成时给确定感（属系统语言，不占暖金）。

ui:whisper

低语条

星澜正在说时浮现，说毕停留 1.4s 淡出，跨态可见实时回复。

5.4 状态切换（三态导航状态机）

home / 首页

星澜在场 + 协同对话 + 感知浮层（默认态）。

memory / 记忆

goals / 目标

目标河流，意图推进与里程碑。

切换规则：导航以具名状态切换，state:change 事件广播（便于守卫 / 埋点 / 转场动画）；loop 为跨态的「人的环」覆盖层。

5.6 扩展方式

新增一种关注方 = 只加一个订阅者

例如要新增「音效反馈」或「埋点上报」：只需 bus.onType('ui:toast', ...) 订阅对应事件，无需改动任何生产方代码。事件源（emit）保持稳定，系统随业务增长而清晰。

Responsive & Multi-device

六、响应式与多端适配

设计以桌面 Web 为基准，但须保证在平板与手机上仍可「在场、可对话、人的时刻可见」。以下为断点与适配规则。

断点布局星澜与导航关键约束
≥1200双栏（对话主 + 感知侧）版本 A / B 任选最大内容宽 1180px
768–1199单栏，感知浮层叠于对话上星澜居中或左置，字号↓网格降 2 列
<768单栏竖排三态导航转底部 Tab；星澜英雄区收窄触控热区 ≥44px；expr 卡 2 列
移动端规则
  • • 导航：底部 Tab（首页/记忆/目标），图标 + 文字。
  • • 星澜：英雄区高度压缩，核心 ≥48px 可见。
  • • 对话：气泡满宽 90%，输入区固定底部。
  • • 人的环：全屏暖金确认卡（modal）。
降级与性能
  • • 窄屏隐藏非关键装饰（星云/外环）。
  • • 动效在低端机降帧或关闭 ripple。
  • • LCP < 2.5s；长列表虚拟滚动。
Accessibility

七、可访问性基线（a11y）

深空暗色 + 低透明文字对可读性构成挑战，须以规范守住底线。以下为强制基线，实现须逐条满足。

对比度与字号
  • • 正文 ≥14px；辅助文字 ≥12px（--ink-faint 仅用于 ≥12px 标签）。
  • • 正文对比度 ≥4.5:1；大文本（≥18px）≥3:1。
  • • 冰青 --core 仅用于非纯文本关键点或配合文字。
焦点 · 动效 · 语义
  • • 所有可交互元素可见焦点环（--core 描边）。
  • • prefers-reduced-motion：停呼吸/涟漪，核心静态常显（本稿已内置适配）。
  • • 星澜标识 role="img" + aria-label；状态变化经 live region 播报。
  • • 表情演示提供文本等价（如「等待你」标签）。

强制：未通过对比度与 reduced-motion 走查的页面，不得合入主分支。
