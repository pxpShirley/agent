Design Principles

设计原则

以「关系」而非「工具」为第一性。星澜不是功能列表，而是一个在场的存在；界面应让这种在场可被感知、可被信任、可被依赖。

01

唯一焦点

每屏只立一个视觉主角——星澜。其余信息退为氛围与浮层，绝不抢戏。

02

静水深流

克制的动效与留白。呼吸、浮现、淡入，而非闪烁、弹跳、堆叠。

03

冷暖有界

冷青是系统的语言，暖金只留给「人的时刻」——需要你、确认、人的环。

04

渲染而非罗列

对话输出是结构化渲染（Markdown），记忆/目标是图谱而非表格，信息以「形态」表达。

Information Architecture

信息架构（IA）

顶层为三态导航（首页 / 记忆 / 目标），「人的环」是跨态的确认时刻；后台由四步 Agent（规划→检索→执行→复核）驱动「进行中」与「需要你」。

主场域（首页/星澜） 人的时刻（需要你） 次级态 / 后台
◉

在场陪伴

星澜常驻、呼吸、状态可见；进入即被「看见」，离开即回归静默。

✦

感知建议

主动推送「此刻该留意的事」，而非等你来翻。

❏

协同对话

多轮对话，输出以 Markdown 结构化渲染；支持步骤内联展开。

◈

记住与你的关系事实，以星座形态聚类、可回溯、可信任。

⇲

目标推进

◍

⚙

后台执行

规划 / 检索 / 执行 / 复核 四步 Agent，驱动「进行中」与「需要你」。

Layout Decision

布局决策（B 基准 · A 备选）

原型 v0.4 并列了版本 A（星澜左置）与版本 B（星澜居中）。本版选定版本 B 为基准实现：它与 persona v1.2 的 HomeComposite（星澜居中 hero + 双栏）一致，最契合「唯一焦点」原则；版本 A 降为窄屏/长对话备选。

版本 B · 星澜居中英雄 基准 BASE

  • 结构：顶部英雄区（星澜居中＋问候/状态/字幕）→ 下双栏（对话主区 ｜ 感知侧栏）。
  • 理由：第一眼即焦点，仪式感强，最贴合「在场存在」；首页/记忆/目标三态共用同一 hero 语言。
  • 适用：陪伴、确认、关系型场景（默认桌面端）。
  • 窄屏：英雄区压缩、双栏竖向堆叠、底部 Tab 导航（见 §响应式）。

版本 A · 星澜左置沉浸 备选 ALT

  • 结构：左固定星澜栏（96px）→ 中对话主区 → 右感知浮卡。
  • 保留价值：长对话、深度协同时信息密度更高，星澜「在身边」。
  • 合并要点：二者共享全部模块（M1–M6）与令牌；仅差异在 hero 位置与栏布局，可作为「对话专注模式」开关切换，不另起一套实现。

Key Modules

关键界面模块规格

六个跨版本复用的核心模块。编号 M1–M6，定义其构成、状态与交互。

M1 · XinglanCore

星澜核心

呼吸光核 + 状态环 + 记忆计数。空闲仅留核心与一层细环；工作时对应节点（规划/检索/执行/复核）浮现。

  • 状态随统一状态机切换（见 §9）
  • 字幕随对话流更新
states: calm / listening / thinking / speaking / waiting / happy / concerned / sleeping
M2 · Conversation

协同对话流

气泡序列，assistant 以 Markdown 渲染（标题/列表/代码/引用/表格）。回合可内联展开 Agent 步骤。

  • 流式打字效果
  • 建议 chip 触发发送
states: idle / streaming / done / error
M3 · Perception

感知浮层

三类轻量卡：此刻建议 / 进行中（含进度条）/ 需要你（暖金）。可浮于对话之上或置于侧栏。

  • 「需要你」独占暖金
  • 低打扰、可收起
states: suggest / in-progress / need-you
M4 · Dock

三态导航

首页 / 记忆 / 目标 极简导航。当前态以冰青高亮，切换带 1.1s 色调过渡。

  • 无文字冗余
  • 支持 @指令直达
states: home / memory / goals
M5 · Composer

输入与指令

文本输入 + @记忆/@目标/@首页 指令。空发送在 首页→记忆→目标 循环切换。

  • placeholder 引导
  • Enter 发送 / Shift+Enter 换行
states: empty / typing / sending
M6 · Constellation / River

记忆星座 · 目标河流

记忆态以星座聚类呈现关系事实；目标态以河流呈现意图与里程碑。两者均以「形态」而非列表表达。

  • 悬停展开详情
  • 点击回溯对话
states: populated / empty / loading
Interaction Flow

核心交互流程

从进入到回到在场的完整闭环，标注系统态与人的时刻。

1

进入 · 在场

星澜 greeting，状态 listening，展示记忆计数与当日感知。

2

发起协同

用户输入或点建议 chip，进入对话；@指令可直跳他态。

3

思考 · 浮现

状态 thinking，Agent 节点（规划→检索→执行→复核）依次浮现。

4

渲染输出

流式返回，assistant 气泡以 Markdown 渲染，可展开步骤。

5

需要你

暖金 human's ring 提示，用户确认 / 选择 / 忽略。

6

沉淀 · 推进

结果记入记忆（星座）或推进目标（河流）。

7

回归在场

回到静默陪伴，等待下一次发起。

常态（home/memory/goals） loop · 人的环（瞬时、跨态）

状态机 = { home, memory, goals, loop }。home/memory/goals 经 Dock 点击或 @指令互斥切换；loop 由 confirm:open 瞬时进入、覆盖当前态，确认/忽略/超时后回原态。事件广播遵循 persona v1.2 §5（13 类交互事件）。

States & Edge Cases

状态反馈与边界情况

覆盖加载、成功、错误、空态、离线/超时、人的环超时降级与流式中断。每条给出迷你预览、说明与恢复路径。

加载 / 思考中thinking
规划检索执行复核
星澜核心转入 thinking，四步 Agent 节点依次亮起；对话区显示打字指示器。最长 180s 预算（见边界「超时」）。
↳ 可随时点停止；节点完成自动熄灭。
成功success
✓ 已记入记忆（星座）
任务收下/完成时：冰青脉冲（~2.2s）轻提示，属系统语言、不占暖金。重大完成可同步推进目标河流进度。
↳ 提示自动消失，无阻断。
错误 + 重试error
⚠ 暂时没连上，没拿到结果
接口返回非 2xx / 解析失败：对话气泡标 error，附 重试 入口；不弹出模态，不打断在场。
↳ 重试复用原请求；连续失败升级为离线横幅。
空状态empty
✦还没有记忆
和星澜聊聊，关系会慢慢长出来
记忆态/目标态首次为空：以 引导文案 + 一个发起动作 替代空列表；目标态空时引导「说一个这周想推进的事」。
↳ 用户首条对话后自动填充星座/河流首节点。
离线 / 网络超时timeout
⚠ 网络较慢，已等待 180s 仍无响应
可为这次任务稍后重试
超过 180s 总预算（server 侧已放宽 90→180s，避免「查网络超时」式中断）：顶部暖金横幅说明，提供 稍后重试，不丢输入。
↳ 网络恢复后横幅消失；草稿保留在输入框。
人的环超时降级loop-timeout

动效原则

呼吸核心 4.2s ease-in-out 无限，幅度 ±7%
浮现节点/卡片 opacity+translateY 8px，.4s
过渡态切换 1.1s 色调渐变（cubic-bezier(.22,.61,.36,1)）
旋转外环 18s 线性，仅作极淡氛围
用慢、柔、少；动效服务于「在场感」与焦点引导。
忌弹跳、闪烁、同时多元素强动效，避免噪点。
